## 2026-09-29 — Widget identity verification

If your site passes `user_id` in `userHints` so a visitor's conversation follows them across devices, you can now prove that `user_id` really belongs to the visitor, instead of trusting it as-is.

**Who's affected:** any site passing `user_id` to the widget.

**What changed:** a tenant owner can generate a signing key in **Dashboard → Widget settings → Widget identity verification**. Your server computes a `user_hash` from the key and the visitor's `user_id`, and passes it alongside `user_id` in `userHints`. Once a key is configured, cross-device resume requires a valid `user_hash` — a bare `user_id` becomes personalization only, and every new browser starts a fresh conversation.

Sites that don't set up a key keep today's behavior for now, but that unverified fallback will be removed in a future release — set up verification now.

See [Embedding the Widget → Identity verification](/docs/embedding-the-widget#identity-verification) for the full setup guide.
