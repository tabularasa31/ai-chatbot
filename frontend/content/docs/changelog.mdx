## 2026-10-17 — Inline widget fills its container

An inline widget (`mode: "inline"`) now takes the height of its target element instead of a fixed 600px, so a shorter target no longer cuts off the message box. A target without a height still gets 600px.

**What to do:** nothing. To size the widget, give the target element a height. See [Embedding the widget](/docs/embedding-the-widget).

## 2026-10-17 — New widget look

The chat widget has a new look.

- The header is always dark and now carries "Powered by Chat9", so the footer is gone and the message box sits closer to the bottom.
- The send button, your visitor's messages and the launcher use the `color` you pass to `Chat9Widget.start`; the rest of the panel keeps its own colours.
- The launcher hides while the chat is open. Close the chat with the X in the header or the Escape key, and focus returns to the launcher.
- On desktop you can resize the chat by dragging the corner of the header, or with the arrow keys once the resize handle has focus.

**What to do:** nothing. See [Embedding the widget](/docs/embedding-the-widget) for the options.

## 2026-10-17 — Widget code block colours

Code blocks in the widget now show readable text and a correctly coloured copy button in the light theme.

## 2026-10-17 — Docs follow your theme

The documentation now follows the light or dark theme you chose, with the theme switch at the bottom of the sidebar. Inline code and headings are easier to read, and text lines are shorter on API pages.

**What to do:** nothing.

## 2026-10-17 — New website and blog design

The Chat9 website and blog have a new design.

- They support light and dark themes, with a theme switch in the footer.
- The home page shows a live demo of the widget next to the sign-up button, and describes setup and handoff to your team step by step.
- Blog articles open as a single column, and the blog index is a list of articles.

## 2026-10-17 — Settings redesign and dark mode for the dashboard

**Settings:**
- The four tabs (**Bot**, **Widget**, **Team**, **Seats**) are laid out as plain sections, each with its own Save button that is active only when something changed.
- Removing the OpenAI key, rotating the identity key, removing a team member and deleting the tenant now ask for confirmation in a dialog.
- The support inbox **Clear** button is gone: empty a field and save to unset it.
- The seat price appears once, on **Seats**.
- Wording: the company account is now called a **tenant** everywhere. "Workspace" is retired.

**Dark mode:** the whole dashboard follows your colour scheme. Pick System, Light or Dark with the switch at the bottom of the menu.

**What to do:** nothing. See [Dashboard Features](/docs/dashboard-features) for where each setting lives.

## 2026-10-17 — Widget: new look and dark theme

The chat window and the chat button have been redesigned for every widget.

- New `theme` option: add `theme: "dark"` to `Chat9Widget.start()` for dark sites. Without it the widget stays light.
- The header shows a neutral **Assistant** name, without an online status.
- A close button in the header, and Escape closes the chat. On phones the chat opens full screen.
- When something goes wrong, the chat says what happened in plain words and offers **Try again**; your visitor's message is kept.
- Source links show the site name as text instead of a site icon, so the widget no longer requests icons from Google.
- The chat button is a flat violet circle by default; the `color` option still overrides it.

**Who it affects:** your visitors, on every site with the widget.

**What to do:** nothing. Set `theme: "dark"` if your site is dark. See the options in [Embedding the widget](/docs/embedding-the-widget#configuration).

## 2026-10-16 — Dark dashboard menu and top bar

The dashboard menu and top bar are dark again, in both the light and dark themes, so they stand apart from the page. In the dark theme, the page area is a little lighter than before.

**What to do:** nothing.

## 2026-10-16 — Inbox and Analytics redesign

**Inbox:**
- One panel layout for the list and the conversation.
- Conversations are marked **Waiting** or **Live** only.
- Bot and operator replies render formatting: lists, links and code.
- Your own replies say "You".
- "Answered by email" is shown inline in the conversation.
- If another operator takes a conversation first, you get a clear message instead of a silent failure.
- The **All** tab can be linked to directly with `?scope=all`.

**Analytics:** each metric is listed with what it means, with links to **Inbox** and **Doc gaps**.

**What to do:** nothing. See [Dashboard Features](/docs/dashboard-features) for where each section lives.

## 2026-10-16 — Redesigned sign-in pages

Sign in, create account, email verification, password reset and team invitation pages have been redesigned.

- They support light and dark themes, with a theme switch under the form.
- Errors are in plain words instead of technical messages.
- The password rule is shown when you create an account or choose a password, and is checked before you submit.
- An expired reset or invitation link offers **Request a new link**.
- There is no delay after signing in.

**What to do:** nothing. See [Getting started](/docs/getting-started) for creating an account.

## 2026-10-16 — Knowledge and Doc gaps redesign

**Knowledge** has a new layout: documents and URL sources share one table, and a document's health is shown inline instead of in a hover tooltip. Deleting a file, a URL source or an indexed page now asks for confirmation and says what will be removed. **Accept all** on the FAQ tab asks first and states how many answers go live. Rejecting a FAQ answer asks first because the answer is deleted.

**Doc gaps** is easier to scan:

- The two columns are now two tabs: **Visitor questions** (formerly Mode B) and **Docs coverage** (formerly Mode A). Each tab shows how many gaps it holds.
- A **Show** filter (Open, Archived, All) replaces the Active and Archive view switch and the per-column filters.
- Coverage is shown as a percentage, for example "About 18% covered", instead of a raw score. The internal signal number is gone.
- **Dismiss** is one click with an **Undo** note. Gaps with a draft in progress ask for confirmation instead.
- Gaps you marked as resolved now appear under **Archived**, in **Closed**. Before, they were listed nowhere.
- Draft previews for Docs coverage open in a side panel instead of pushing the list down.

**What to do:** nothing. See [Dashboard Features](/docs/dashboard-features) for the updated Doc gaps and Knowledge sections.

## 2026-10-16 — New dashboard menu

The dashboard sidebar is regrouped into fewer items.

- **Install widget** replaces **Dashboard** and **Embed**: your bot ID, embed snippet and options are on one page.
- **Settings** is one menu item with four tabs: **Bot**, **Widget**, **Team** and **Seats**. These used to be separate items.
- **Doc gaps** is the new name of **Gap Analyzer**.
- **Knowledge** is the new name of **Knowledge Hub**.
- **Platform metrics** is the new name of **Admin** (visible to platform admins only).

Notices are now ranked by urgency. An OpenAI key problem (missing, rejected or out of credits) is shown at the top of every page; for owners the button goes to Settings → Bot or to your OpenAI billing. Product announcements appear as a quiet note on **Install widget**.

URLs are unchanged, and `/embed` now redirects to the **Install widget** page.

**What to do:** nothing. See [Dashboard Features](/docs/dashboard-features) for where each section lives.

## 2026-10-16 — One typeface across the product

The dashboard, website, sign-in pages and docs now use one typeface, Geist, instead of Arial or the browser's default serif.

**Chat widget:** the widget on your site now uses the visitor's system font and downloads no font file. Text may look slightly different from before.

**What to do:** nothing. Colours are unchanged; text may be spaced slightly differently.

See [Embedding the widget](/docs/embedding-the-widget) for widget setup.

## 2026-10-16 — Clearer errors in Settings, Inbox, Seats and embed snippet

Dashboard pages now say so when data fails to load, instead of showing empty or misleading values.

**Settings:** if part of the page fails to load, that section shows an error with a **Retry** button instead of empty fields. Saving can no longer replace your stored bot instructions, support inbox email, escalation language or response level with blanks. Each settings card shows its own save errors.

**Inbox:** the list no longer says nobody is waiting when it failed to load, and a failed refresh keeps the current list on screen and shows a Retry button. The last-message preview shows "You:" only for your own replies and the colleague's email for replies from others.

**Seats and the Dashboard embed snippet:** both show an error with a Retry button instead of "$0" or an empty snippet when their data fails to load.

**What to do:** nothing. Owners may want to confirm their bot instructions and support inbox email in Settings.

See [Dashboard features](/docs/dashboard-features) for the Settings and Inbox pages.

## 2026-09-29 — Widget identity verification (optional)

You can now verify that a `user_id` passed to the widget really belongs to the visitor.

**What's new:** generate a signing key in **Dashboard → Widget settings → Widget identity verification** (now Settings → Widget). Your server computes a `user_hash` from the key and the visitor's `user_id`, and passes it alongside `user_id` in `userHints`.

**Why you might want it:** without a key, user IDs are trusted as-is, so anyone who knows or guesses a visitor's ID can open their conversation. With a key, only visitors with a valid `user_hash` restore conversations across devices and are grouped in the Inbox; unsigned IDs only personalize the chat and keep it in the same browser.

See [Embedding the Widget → Identity verification](/docs/embedding-the-widget#identity-verification) for the full setup guide.
